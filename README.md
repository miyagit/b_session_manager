# b_session_manager

## LIFF（スタッフ向け実績報告）

スタッフは LINE から LIFF アプリを開き、その日の実績を報告できます（`/liff`）。現場は管理者が登録した稼働予定（稼働場所・稼働日・ブース予算）とシフト（スタッフ・前半/後半/全日）から自動で決まるので、現場や予算の入力は不要です。個人目標（獲得件数・アプローチ）は当日の開始報告でスタッフが入力します。

報告は3種類あります。開始報告（個人目標の入力）、途中報告（13時・16時・19時の累計の獲得件数とアプローチ）、最終報告（確定の獲得件数・アプローチ・カード数と、1分単位の勤務時間）。同じブースのスタッフ全員分を1人がまとめて報告できます。

### LINE Developers の設定

1. Messaging API チャネルと**同じプロバイダー**に LINE ミニアプリチャネル（または LINE ログインチャネル）を作成する（ユーザーIDを一致させるため）。ミニアプリの場合、LIFF の設定は「ウェブアプリ設定」タブにまとまっており、開発用・審査用・本番用で LIFF ID が異なります。
2. そのチャネルに LIFF アプリを追加する。
   - エンドポイントURL: `https://<公開ホスト>/liff`（開発中は ngrok などのトンネルURL）
   - スコープ: `openid` と `profile`
   - サイズ: Tall または Full
3. LIFF ID（ミニアプリなら使う環境のもの。開発中は開発用、公開後は本番用）とチャネルIDを環境変数で渡す（下記）。
4. グループに貼る・リッチメニューに登録する URL は `https://miniapp.line.me/<LIFF ID>`（LINE ログインチャネルの LIFF なら `https://liff.line.me/<LIFF ID>`）。

### 環境変数

秘密情報は encrypted credentials ではなく環境変数で渡します。開発・テスト環境では `dotenv-rails` がプロジェクト直下の `.env` を読み込みます（`.env*` は git 管理外）。本番ではデプロイ先の環境変数に設定してください。

| 環境変数 | 内容 |
| --- | --- |
| `LINE_CHANNEL_SECRET` | Messaging API チャネルのチャネルシークレット（Webhook 署名の検証） |
| `LINE_CHANNEL_TOKEN` | Messaging API チャネルのチャネルアクセストークン |
| `LIFF_ID` | LIFF アプリの LIFF ID |
| `LINE_LOGIN_CHANNEL_ID` | LIFF を作ったチャネル（ミニアプリチャネル／LINE ログインチャネル）のチャネルID。IDトークンの検証に使う |
| `LINE_REPORT_GROUP_ID` | 実績報告を投稿する LINE グループのID（下記） |
| `SECRET_KEY_BASE` | 本番のみ必須。開発・テストでは Rails が `tmp/local_secret.txt` に自動生成します |
| `B_SESSION_MANAGER_DATABASE_PASSWORD` | 本番DBのパスワード（`config/database.yml` 参照） |

スタッフの特定は、LIFF の IDトークンを LINE の verify API で検証し、その `sub`（LINEユーザーID）を `users.line_uid` と突き合わせて行います。

### ランキング（管理画面）

管理画面の「ランキング」で、月ごとの「総獲得件数」「獲得平均（ドンキ・勤務6時間あたり）」「獲得平均（シネマ・1日8時間あたり。拘束9時間から休憩1時間を除く）」の順位を 1 位から最下位まで見られます。平均はそれぞれの現場で勤務した人だけが対象です。全員表示では名前の代わりに「ー」を出すので、そのままスタッフに共有できます。「上位5名のみ（フルネーム）」に切り替えると上位 5 名が本名で表示されます。本名入りの一覧は分析（スタッフ別）にあり、そこにも順位と 6 時間あたりの列があります。LIFF にランキングはありません。

ブース予算はドンキホーテの稼働予定でのみ必須です。シネマは未記入でよく、その場合は達成率と投稿文の予算行が省かれます。

### スタッフの登録と LINE 連携

1. 管理者が「スタッフ」画面で名前を登録する（この時点では LINE 未連携）。稼働予定とシフトはこの名前で先に組めます。
2. スタッフが LIFF を初めて開くと、同意画面のあとに「あなたの名前を選んでください」が出るので、自分の名前を選んで確認する。これで LINE アカウントとスタッフが結びつき、次回からはこの画面は出ません。報告はしなくて構いません。
3. 間違えて選んだときは、管理者がスタッフ編集画面の「LINE連携を解除」で解除すると、次回開いたときに選び直せます。

友だち追加（follow イベント）や LIFF の初回ログインでスタッフが自動作成されることはありません。公式アカウントの友だち追加も必須ではありません。

### 実績報告の LINE グループ投稿

投稿文（【開始報告】【〇時途中報告】【最終報告】の書式）は `LineReportMessage` が組み立て、投稿結果は `line_message_deliveries` に記録されます。投稿方法は2つあり、`LINE_REPORT_GROUP_ID` の有無で切り替わります。

**スタッフ本人が LIFF から投稿する（標準・無料）**
報告の完了画面に「LINEグループに投稿」ボタンが出ます。LINE の送信先選択（シェアターゲットピッカー）で実績報告グループを選ぶと、スタッフ本人の発言として投稿されます。LIFF をグループに貼った URL から開いた場合は、選択なしでそのグループに直接送ります。
- LINE Developers の LIFF 設定で「シェアターゲットピッカー」を ON にし、スコープに `chat_message.write` を追加する。
- メッセージ数にはカウントされません。

**公式アカウントから自動で push する（任意・有料枠に注意）**
`LINE_REPORT_GROUP_ID` を設定すると、報告保存時にジョブが公式アカウントからそのグループへ push し、失敗は報告詳細の「LINEに投稿する」で再送できます。
1. Messaging API チャネルで「グループトーク・複数人トークへの参加を許可」を ON にする。
2. 公式アカウントをグループに招待する。join イベントを受けて公式アカウントがグループIDを返信します。
3. その値を `.env` の `LINE_REPORT_GROUP_ID` に設定し、サーバーを再起動する。
push は月間メッセージ数にカウントされます（1ブース1日あたり5通）。

シフト区分は、前半 10:00〜16:00・後半 16:00〜22:00・全日 10:00〜22:00（ドンキホーテ）、シネマ 10:00〜19:00（シネマ）の4種類です（`Shift::FIXED_HOURS` で変更可）。全日は 9 時間のフレックス勤務で、開始報告で開始時刻（10:00 以降）を入力し、終了は開始＋9時間になります（22:00 を超えても構いません）。最終報告では、ドンキのシフトについて実際に働いた開始・終了時刻を入力します（予定の時刻が初期値。残業や早退をそのまま記録）。この値は `work_records` テーブルに保存され、獲得平均の計算に使われます。シネマは時間が固定なので入力しません。

### ローカルでの動作確認

development 環境では `/liff` に「開発用ログイン」が表示され、LINE を使わずにスタッフを選んで報告画面を開けます。
